The rubric is part of the model

I graded more than 100 teleoperated robot demonstrations frame by frame. The most important thing I built wasn't the policy. It was the written standard that decided what the policy got to learn from.

Sep – Dec 2025 project·6 min read
TL;DR
  • Task: multi-stage object stacking on the SO-100 arm. I collected 100+ teleoperated episodes and trained ACT with SmolVLA pre-training.
  • Every episode was split into five phases and scored against eight criteria as Pass, Borderline or Fail. Any Fail meant reject.
  • The hard part was the edge cases: a slipped-then-recovered grasp, an object that drifts after release, an operator who pauses.
  • Any rubric change meant re-grading every earlier episode. A dataset graded against two standards is effectively unlabelled.

Why a written standard

Imitation learning copies what it sees. Show it a hesitant grasp and it learns hesitation. Show it a "success" where the stack wobbles off a second later, and it learns that's fine. So the question "which episodes go in the training set?" is a modelling decision, not a cleaning chore. I wanted every one of those decisions to be written down, consistent and auditable, not made by feel at 1 a.m. on episode 87.

Curation is a loop: what the policy gets wrong feeds back into the standard.

Step 1: cut every episode into phases

You can't grade "the episode" as one blob. Each one was segmented into sub-actions, with a single rule for boundaries: a phase starts on the first frame where its start condition holds. One rule, applied everywhere, is what makes two people (or me on two different days) put the boundary on the same frame.

PhaseStarts whenEnds when
ApproachArm starts moving toward the objectGripper is around the object, not yet closing
GraspGripper starts closingObject lifted clear and held stably
TransportObject leaves the surfaceObject is above the target stack
PlaceDownward motion onto the stack beginsObject rests on the stack
Release & retreatGripper starts openingGripper clear, stack still

Step 2: eight criteria, three grades

Each criterion scores Pass, Borderline or Fail. Any single Fail disqualifies the episode, and too many Borderlines do too. The criteria cover completion, approach, grasp, object control, placement, release, whether the boundaries can be marked at all, and whether the recording itself is valid. Three failure types needed especially sharp definitions:

  • Partial grasp: the object is held by an edge, slips or is dropped.
  • Object drift: the object shifts in the gripper, or on the stack after placement.
  • Unstable approach: oscillation, repeated aborts, or contact before the grasp.

Step 3: rule on the edge cases once

The clear successes and clear failures are easy. The project lived or died on the ambiguous ones, so each got a written ruling with a reason:

SituationRulingWhy
Grasp slips, then recovers within the phaseBorderlineRecovery is useful to show, but too much of it teaches hesitation
Object lands right, then drifts after releaseFailThe end state isn't stable, so it would teach a false "success"
Operator pauses mid-transportPass, if motion resumes on the same pathA pause isn't an error; a changed path is
Task done in a different valid orderFailThe policy must learn the instructed order

Step 4: never let the standard drift

Halfway through a long review, you sharpen a definition. The tempting move is to apply it from here on. That's how you end up with a dataset where episode 20 and episode 80 were judged by different rules, and the model gets contradictory lessons. My rule: every rubric change means re-grading every episode already reviewed. Each grade logs the rubric version, and each reject carries a criterion code and the frame number where the failure starts, so anyone can audit it.

Step 5: read the failures backwards

After training ACT with SmolVLA pre-training, I watched the rollouts and sorted failures into two kinds, because they point to different fixes:

FailureWhat it looks likeData-side fix
Perception errorArm moves confidently to the wrong place, or picks the wrong objectCheck coverage of lighting, camera pose and occlusion; check recording validity
Trajectory errorRight target, poor motion: hesitation, overshoot, failed graspTighten approach, grasp and control criteria; remove borderline demos of that phase
Boundary decisions and accept/reject strictness flow straight into the policy's behaviour. The rubric is part of the model.

This is also why I'm now running a controlled study of data errors on a VLA. On real data like this I could see that the data mattered, but I couldn't measure by how much. In simulation, I can.
