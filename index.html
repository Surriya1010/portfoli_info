Research · in progressNov 2026 – present

Which training-data errors break a VLA policy?

TL;DRMeasures which real-world data errors hurt a robot policy most, and whether cheap checks catch them first.

A controlled study of how realistic demonstration-data errors (timestamp offsets, task-label noise, operator-style corruption) change a vision-language-action policy. Each error is injected on its own, at set strengths, into Franka/LIBERO data. The same smolVLA model is fine-tuned on each version, and the drop in task success is reported across seeds with 95% confidence intervals. The study also tests whether cheap checks catch each error before training. The design and a tested corruption and detector library are public; experiments are in progress.

NVIDIA GR00T N1 closed-loop in Isaac Lab 3.0

TL;DRGot a 2B-parameter humanoid foundation model running closed-loop in simulation, across two Python stacks.

Runs NVIDIA's 2B-parameter GR00T N1 VLA closed-loop on GR1-T2 humanoid manipulation tasks. A localhost bridge connects the simulator (Python 3.12) to the policy server (Python 3.10) and matches the reference image preprocessing, with a hold-pose baseline mode for comparison.
